# AEV-PLIG in JAX: structure store, on-the-fly AEVs, vanilla reproduction, profiled loop

Date 2026-11-07. Status: reviewed (builder check) and decisions settled with the user; implementation plan at `docs/superpowers/plans/2026-11-07-aevplig-jax-rewrite.md`.

## 1. Intent and why

AEV-PLIG (oxpig release 3ccac4b) trains one seed in 54 to 58 minutes on a GH200 (200 epochs over 95,680 ligand graphs, batch 128, PyG collation in the main process, no loader workers). The user wants the model rewritten in JAX so that a seed trains several times faster, because fast iteration is what made the jax-Ka GQT recipe (run 4 -> hmask -> dRSA) succeed, and because the next architecture steps (a protein-pocket graph encoder and a ligand graph encoder with per-branch auxiliary heads, a shared regressor, dRSA/edge heads, then Siamese/consistency terms) will be built on this loop.

This piece delivers the foundation only: (1) a structure store built from the archives, holding coordinates and types, with the radial AEVs computed in JAX on the fly; (2) the vanilla AEV-PLIG model and training loop in JAX, reproducing the released model; (3) profiles of the PyTorch loop and the JAX loop showing where the time goes and that the on-the-fly AEVs add negligible overhead. It also leaves the data and code shaped for the pocket encoder, without building it.

## 2. Goals, non-goals, anti-goals

Goals
- G1. A versioned record store of every processed training-side complex, FEP-benchmark and 15-PGDH complex (97,857 + 1,184 + 43; the paper's split uses 96,950 of the first group) with ligand heavy-atom coordinates and RDKit features, bonds, and all protein heavy atoms within 10 A of any ligand heavy atom with their 22-type code and residue annotation. Single-file stores (inode budget).
- G2. Radial AEVs computed in JAX inside the training step from the store, reproducing the pickled features to float precision.
- G3. The vanilla model and recipe in JAX, reproducing the released numbers at 10 seeds (section 8).
- G4. Measured wall time per seed at most 10 minutes for 200 epochs including per-epoch validation (at least 5x the PyTorch loop), loader wait under 5% of wall time, padding waste under 25% of node slots. If the target is missed, the profile report says where the time goes and what the next lever is.
- G5. A profile of both loops (PyTorch baseline and JAX) in one report with a table, plus an A/B of on-the-fly AEVs against precomputed AEVs on the same batches: on-the-fly must add under 10% to step time.
- G6. Code shaped for the next steps: the encoder is a function from a batch to per-node embeddings separate from the heads; the loop supports several weighted loss terms and reports each; selection uses the primary metric only; the store has the pocket atoms and residue ids the pocket encoder needs; Zernike invariants and later RSA join as side tables keyed by id.

Non-goals (this piece)
- No pocket encoder, no auxiliary heads, no Siamese/consistency terms, no new augmentation. Those are the next pieces and get their own designs.
- No change to the model's maths, data, split, seeds or selection rule. The reproduction is only a check if nothing moves.
- Matmul precision: TF32, JAX's float32 default on Hopper and what jax-Ka production trained with (user decision 2026-11-07). The ten-seed reproduction is the test of it; strict float32 (`jax.default_matmul_precision("highest")`) is the first rerun if the reproduction misses. bf16 is a later speed arm, judged at 10 seeds.
- No angular AEV terms, no new atom types.

Anti-goals (would make it a failure even if it runs)
- A JAX model that trains faster but does not reproduce the released CASF and FEP numbers within seed noise.
- A loop whose speed comes from changing batch composition, selection or evaluation in ways that make results incomparable with the paper's protocol.
- Writing anything under `/scratch/u6xq/hussain.u6xq/aevplig/` (the parent session's tree; read-only here), or running compute on a login node, or scattering small files on scratch.

## 4. What is being reproduced (semantics the JAX model must match)

From `model_defs.py`, `utils.py`, `isambard/jobs/train_seed.py` and PyG 2.5.3 `GATv2Conv`:
- Node features 367 = 15 RDKit (one-hot of F,N,Cl,O,Br,C,B,P,I,S; heavy-neighbour count; H count; explicit valence; aromatic; in-ring) + 352 radial AEV. Edge features 4 = one-hot bond type over [single, aromatic, double, triple]. Heavy atoms only; both bond directions present; edges sorted by (source, target).
- Radial AEV, per ligand heavy atom i, species s in 1..22, shift k in 1..16: `aev[i,s,k] = sum_{j != i, species_j = s, r_ij < 5.1} 0.25 * exp(-19.7 (r_ij - Rs_k)^2) * (0.5 cos(pi r_ij / 5.1) + 0.5)` with `Rs = [0.80, 1.07, 1.34, 1.61, 1.88, 2.14, 2.41, 2.68, 2.95, 3.22, 3.49, 3.76, 4.03, 4.29, 4.56, 4.83]`. The environment is the protein atoms only: `torchani_mod.aev.trim_neighbor_pairs` keeps ligand-to-protein pairs and drops ligand-to-ligand ones, so ligand atoms are centres and never neighbours (their atomic-number-6 coding is moot). A protein atom counts when its PDB atom name maps to one of the 22 `ATOM_TYPE` codes in `data/PDB_Atom_Keys.csv` (type index = order of first appearance + 1). Column order of the 352 is species-major, shift-minor. Protein atoms were pre-cropped to the ligand bounding box padded by 5.2 A; a 10 A sphere crop is a superset, so the sums are unchanged. The builder reads `LoadPDBasDF` in `generate_pdbbind_graphs.py` to replicate exactly which PDB atoms are kept (HETATM, altlocs, hydrogens, unmapped names) and the ligand reading path per source: BindingNet (and the paired tree's FEP and 15-PGDH featurisers) use `SDMolSupplier(removeHs=False)`; PDBbind and BindingDB use `MolFromMol2File` then `AddHs(addCoords=True)`, which sets the H-count feature; heavy atoms in RDKit order (`mol_to_graph`).
- GATv2 layer (PyG defaults): self-loops added for every node with edge feature = mean of that node's incoming edge features (zeros if none); `e_ij = a . leaky_relu_0.2(W_l x_j + W_r x_i + W_e e_ij)` with x_j the source, softmax over the incoming edges of i including the self-loop; message `alpha_ij * (W_l x_j)`; 3 heads concatenated to 768; conv bias added; W_l and W_r are separate (`share_weights=False`), W_e has no bias; attention dropout 0. Then `leaky_relu` slope 0.01, then BatchNorm over all real nodes in the batch (momentum 0.1, eps 1e-5, affine). Five such layers: 367 -> 3x256, then 768 -> 3x256 four times.
- Readout: concat(global max pool, global mean pool) = 1536 -> fc1 1024 -> leaky_relu -> BatchNorm1d -> fc2 512 -> leaky_relu -> BatchNorm1d -> fc3 256 -> leaky_relu -> BatchNorm1d -> out 1. All BatchNorms use running statistics in evaluation.
- Loss MSE on standardised pK (`StandardScaler` fit on the training labels; mean and sd stored). Adam lr 1.2291937615434127e-4, no weight decay, batch 128 shuffled over the whole training set each epoch, 200 epochs. Seeds [100, 123, 15, 257, 2, 2012, 3752, 350, 843, 621]. Per epoch: validation Pearson on the 993-row paper valid set; save when the mean of the last eight epochs' Pearson (window clipped at the start) exceeds the best so far. At the end: load the saved weights and predict the test set (CASF, 277). Ensemble = mean of the ten seeds' predictions.
- Initialisation: `init_weights` applies `xavier_normal_` to every module attribute named `weight` outside BatchNorm (GATv2's `lin_l`, `lin_r`, `lin_edge`, the four dense layers); biases and the attention vector `att` keep the library defaults (PyG glorot for `att`, zeros for the conv bias, PyTorch's uniform fan-in bound for `nn.Linear` biases; the builder checks PyG 2.5.3's `Linear` bias initialiser). Distribution-level match is what matters; bit-exact RNG is not a goal.
- Evaluation outside training: CASF Pearson/RMSE via the parent's `isambard/jobs/ensemble_eval.py` format (`output/predictions/<tag>_<dataset>_test_seed<i>.csv` with `truth`, `preds_<i>`); FEP benchmark weighted PCC/Kendall over the 43 series with >= 10 ligands and 15-PGDH pooled Spearman via prediction CSVs consumed by the paired tree's metric code (`paired/src/eval_paired.py`, FEP section) or a small re-implementation.

## 5. Structure store (decided)

- Format: jax-Ka store style. `records.bin` (one zstd frame per complex, arrays in a fixed field order, C-contiguous), `index.npz` (ids, byte offsets, lengths, per-record dims `L`, `E`, `P`, `A` = number of typed protein atoms within 5.1 A of any ligand heavy atom), `metadata.json` (schema version, fields, dtypes, shapes, cutoff, species table, RDKit and build versions), `records.json` (per id: source, split, pdb, label, series keys from the paired work where available), `verification.json` (counts, checksums, parity results). One store per set: `train`, `valid`, `test`, `fep`, `pgdh`. The training-side stores hold every row of the three `*_processed.csv` tables (19,308 + 69,727 + 8,822 = 97,857) with a split label `train` / `valid` / `test` / `excluded` taken from the paper's dataset files (95,680 / 993 / 277; the rest are the ligsim90-filtered rows), so later arms can use the excluded rows without a rebuild. The paired tree's `series_valid` and `group_valid` row lists apply later as id masks.
- Per record fields: `lig_xyz` (L,3) f32; `lig_feat` (L,15) f32; `bond_src`, `bond_dst` (E,) int32 sorted as `mol_to_graph` sorts; `bond_type` (E,4) f32; `prot_xyz` (P,3) f32 for protein heavy atoms within 10 A of any ligand heavy atom; `prot_species` (P,) int8 in 1..22, 0 for atoms kept for the pocket but not in the 22-type table (they contribute nothing to the AEV, as in the original where they were dropped); `prot_res` (P,) int32 residue serial within the record; `prot_resname` (P,) int8 (20 standard + other); `prot_atom` (P,) int16 atom-name code; `prot_chain` (P,) int8; `prot_bfactor` (P,) f16 (optional, zero when absent). Schema 2 (fix wave after the final review) appends `prot_element` (P,) int8 (code into `metadata.json`'s `elements`: other, C, N, O, S, P, H, SE, halogens, metals; from PDB columns 76:78, else the atom name), `prot_chain_id` (P,) int8 (the raw chain character), `prot_resseq` (P,) int32 and `prot_icode` (P,) int8 (0 when blank), so residues match across records of one receptor and join to per-residue tables of the full structure; the schema-1 fields are unchanged and `Store` refuses schema 1.
- Build: `jax/src/aevplig_jax/build_store.py`, run in the AEV-PLIG env inside `jax/jobs/build_store.sbatch`, which extracts the archives to node-local disk exactly as `isambard/jobs/featurise.sbatch` does and processes the three sources in parallel over the 72 cores (multiprocessing, chunked writes merged into one file per set). Generic mode `--csv FILE` with `unique_id, sdf_file, pdb_file` for FEP and 15-PGDH. Estimated size under 1.5 GB per 100k complexes before compression.
- Parity gate: `jax/src/aevplig_jax/aev.py` computes the 352 AEV columns from a record; `verify_store.py` compares, for every record of `train`/`valid`/`test` (and FEP via the paired pickles), the JAX features against the pickled `features[:, 15:]` and the 15 RDKit columns against `features[:, :15]`, and the bond lists; max abs AEV difference must be below 1e-4 and all other fields identical. Results go to `verification.json`. Training refuses a store whose verification is missing or failed.
- Side tables: Zernike invariants are joined by id from the existing npz files (not copied); the three complexes whose pocket descriptors failed carry a missing flag. RSA (free/bound per pocket residue) is a later side table; the store's `prot_res` serials are what it will key on.

## 6. Model and training loop in JAX (decided)

Conventions (from jax-Ka, see `REPORT_jaxka_recipe.md` in the scratchpad and `pkanet/model.py`, `pkatrain/loading.py`): parameters are nested dicts of `{"w", "b"}` arrays and affine `(2, W)` norm arrays; `encode(params, batch) -> (node_embeddings, graph_embeddings)` separate from `heads`; each head's parameters are initialised from `fold_in(fold_in(PRNGKey(seed), HEADS_NS), SALT)` so adding a head never changes the trunk's init (the extra namespace level keeps head keys off the trunk's `split` keys, which partitionable threefry makes equal to `fold_in(key, i)`; later branches take their own namespace constant); three jitted functions at most (loss-and-grad, apply, predict) with the learning rate as a traced argument; a persistent compilation cache under the run directory; `-1e9` masking with float32; every loss term multiplied by `valid`.

- Batch layout (static shapes, one compiled variant): the batch is 128 complexes drawn by PyTorch's scheme, not its RNG stream: a numpy permutation of all training ids from `default_rng([seed, epoch])`, chunked by 128, last chunk short. Exact replay of torch's global RNG is not attempted (that stream is consumed by model initialisation and loader restarts and would need a torch-side export); the protocol is identical and the reproduction is judged at ten seeds. Nodes of all graphs are concatenated: `x_lig` (Ncap,15), `node_graph` (Ncap,) int32, `node_valid` (Ncap,); bonds as padded neighbour lists `nbr` (Ncap,Kb) int32 and `nbr_mask`, `nbr_feat` (Ncap,Kb,4) with slot 0 the self-loop carrying the host-computed mean of incoming bond features; pocket atoms concatenated `env_xyz` (Mcap,3), `env_species` (Mcap,) int8 (protein atoms only); per ligand atom `aev_nbr` (Ncap,Ka) int32 into the pocket arrays and `aev_mask` (Ncap,Ka) (typed protein atoms within 5.1 A, found on the host with `cKDTree`); labels `y` (128,), `valid` (128,). Padded node rows and padded graphs are masked copies of real rows (jax-Ka's spread-padding convention) so no scatter piles onto one row; padded graphs have `valid = 0`.
- Capacities: `Ncap`, `Mcap`, `Kb`, `Ka` are recorded in the store manifest from the data (Kb = max bonded degree + 1 self-loop; Ka = max neighbours within 5.1 A, rounded up to 32; Ncap and Mcap = the maximum batch totals over the deterministic plans of all ten seeds and 200 epochs, computed at manifest time, rounded up to 256 and 1024), so no batch ever overflows and there is no splitting rule. The builder may add a second, smaller capacity tier if the profile shows padding waste above 25%.
- AEV on device: gather `env_xyz` and `env_species` by `aev_nbr`, compute distances, the 16 radial terms and the cutoff, and scatter into the 22 species channels with a one-hot over species (shape (Ncap, 22, 16), then flatten species-major). Masked slots contribute zero. A `--aev precomputed` switch reads the 352 columns from a precomputed table instead (built once from the same store by the same JAX function) so the overhead A/B in G5 compares identical batches.
- GATv2 layer in neighbour-list form: `hl = x @ W_l`, `hr = x @ W_r`, `he = nbr_feat @ W_e`; logits `(a * leaky_relu_0.2(hl[nbr] + hr[:,None] + he)).sum(-1)` per head; masked to -1e9 where `nbr_mask` is 0; softmax over the K axis; message `sum_k alpha * hl[nbr]`; concat heads; add bias; `leaky_relu` 0.01; masked BatchNorm (statistics over rows with `node_valid`, running mean/var updated with momentum 0.1 in training, used in evaluation). Pooling: segment max and segment mean over `node_graph` restricted to valid nodes (padded nodes point at a dump segment). Readout as in section 4. The layer is checked against PyG on random graphs (test with torch available locally; skipped where it is not).
- Loss and optimiser: MSE over valid graphs; `optax.adam(1.2291937615434127e-4)` (vanilla: no clipping, no weight decay). The optimiser is constructed from a small config so the jax-Ka recipe (`clip_by_global_norm(1.0)` then `adamw` with `ndim >= 2` decay mask, hold-then-cosine schedule) can be selected later without touching the loop.
- Loop: `jax/src/aevplig_jax/train.py --seed-index i --tag T --epochs 200` writes `runs/<tag>/seed-<i>/{protocol.json, history.jsonl, checkpoints/epoch-NNN/{state.npz, metadata.json}, selection.json}` (jax-Ka's run-directory shape); per-epoch validation Pearson on the paper valid set; selection by the running mean of the last eight; at the end the selected checkpoint predicts CASF and writes the parent's prediction CSV format. Host side: a `BatchSource` assembling batches in a thread pool (15 threads), jax-Ka's `Prefetcher` (depth 4) doing `device_put` off-thread, `LoaderTelemetry` (wait fraction) and `DeferredScalars` (no per-step host sync; finite check every 50 steps). Loader classes are copied from `pkatrain/loading.py` with a one-line provenance comment.
- Prediction: `predict.py` runs an ensemble of checkpoints over any store (`fep`, `pgdh`, `test`) and writes per-ligand predictions in the CSV formats the existing metric scripts read. `torch_port.py` converts a released or retrained `.model` state dict (including BatchNorm running statistics) into the JAX parameter tree for the parity check in section 8.

## 7. Profiling (decided)

- PyTorch baseline job (`jax/jobs/profile_torch.sbatch`, AEV-PLIG env): the paper's loop on one seed for 3 epochs with `torch.profiler` over 200 steps and epoch timers, reporting time in data collation/transfer vs forward/backward/optimiser; the same with `num_workers=8, pin_memory=True` as a reference point for what the loader alone costs. No change to the clone.
- JAX job (`jax/jobs/profile_jax.sbatch`, jax-Ka venv): `profile.py` runs the training step for 300 steps after compilation and reports: mean/percentile step wall time (`block_until_ready`), loader wait fraction, padding fraction (valid nodes / Ncap, valid env atoms / Mcap), overflow-split count, on-the-fly vs precomputed AEV step time on the same batches, a `jax.profiler` trace of 20 steps (perfetto file) with the top 15 XLA ops by time, and `nvidia-smi dmon` utilisation sampled by the job. Then one full seed (200 epochs with validation) timed end to end.
- Report `jax/work/output/profile/REPORT.md`: one table (PyTorch, PyTorch with workers, JAX precomputed AEV, JAX on-the-fly AEV; per-epoch and per-seed wall; GPU utilisation; loader wait; padding), the op breakdown, and a statement of where remaining time goes and the next lever (bf16 matmuls, fused attention, larger batch) if G4 is missed.

## 8. Acceptance (what done looks like)

1. Store built for train/valid/test/fep/pgdh; `verification.json` shows AEV max abs difference below 1e-4 against the pickles over all train/valid/test records and the FEP pickles, bonds and RDKit columns identical, zero missing complexes relative to the paper's `*_processed.csv`.
2. Weight-port parity: the JAX model loaded with the retrained seed-0 PyTorch weights predicts CASF within max abs 1e-3 pK of the PyTorch predictions (evaluation mode, running statistics, matmul precision `highest` for this check only), and the FEP set within the same bound.
3. Reproduction at 10 seeds on the paper's split: ensemble CASF Pearson within 0.005 of 0.892 and RMSE within 0.02 of 1.041; FEP ensemble weighted PCC within 0.02 of 0.589 and Kendall within 0.02 of 0.429 (the paired-seed sd of wPCC is 0.028, so ensembles of ten agree to about 0.01 to 0.02); the ten per-seed validation Pearsons within the spread of the PyTorch seeds. Any miss is reported with the numbers, not tuned away.
4. Speed: one seed, 200 epochs with validation, at most 10 minutes wall on a GH200; loader wait under 5%; padding waste under 25%; on-the-fly AEVs under 10% over precomputed. If any target is missed, the profile report names the cause and the next lever; the user decides.
5. Tests: a CPU pytest suite under `jax/tests` covering the AEV against a numpy reference on random point sets, the GATv2 layer against PyG, masked BatchNorm against torch on padded input, pooling and loss masking (padding changes nothing), store round-trip and capacities, the sampler following PyTorch's scheme (one permutation of all ids per epoch, chunks of 128, deterministic in seed and epoch), and `torch_port` on a saved model. All green locally in the paired venv (torch available) and in the jax-Ka venv (torch tests skipped).
6. Documentation: `jax/README.md` (layout, commands, environments, timings), `jax/docs/REPORT_reproduction.md` (parity, 10-seed numbers, profile table), the design committed at this path, and the memory note updated with paths, versions and results.
