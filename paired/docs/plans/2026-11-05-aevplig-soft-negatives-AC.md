# AEV-PLIG soft negatives A (shape twins) and C (in-place edits) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build and test two construction-matched soft-negative schemes for AEV-PLIG, selected and placed with the 3D Zernike property descriptors: **A** shape twins (a wrong-chemistry ligand of the same shape overlaid into the pocket) and **C** in-place property edits of the cognate ligand (contact-site edits as negatives, solvent-exposed edits as label-preserving controls), evaluated on a pocket-group-disjoint holdout, the FEP benchmark, CASF and the 15-PGDH set, each with a ligand-only gate.

**Architecture:** Extends `aevplig-paired` (arm-1 and arm-4 plans still apply: `docs/plans/2026-11-05-aevplig-paired-arm1.md`, `docs/plans/2026-11-05-aevplig-pose-decoys-arm4.md`). Two new generators write pose pickles in the arm-4 format with new `kind` codes; the dataset builder ingests any number of such pickles and adds a group-disjoint holdout; the training script gains per-kind loss roles; the evaluator gains a generic negative-discrimination section. All anchors are PDBbind complexes (crystal poses); BindingNet/BindingDB rows are unchanged (kind 0). Descriptors from `work/data/zernike.npz` (shell mode; use standardised `pocket_F` + signed-sqrt `pocket_G`, cosine) and groups from `work/data/pocket_groups.csv`.

**Tech Stack:** as before (torch 2.6.0, PyG 2.5.3, rdkit 2024.3.3, numpy, scipy, pandas, pytest); on Isambard the clone's AEV path through `src/aevplig_featurise.py` (identity-checked in arm 4).

**Spec:** `docs/zernike_soft_negatives_design.md` Part 2 (§2 A and C, §3 pocket characterisation) and the user's answers: build both A and C; positives are regenerated through each scheme's own path with their measured labels; anchors are PDBbind only; the group-disjoint holdout runs beside the existing splits.

## Global Constraints (in addition to the earlier plans)

- **Kind codes** (`kind` column/field): 0 original, 1 near-native, 2 decoy (arm 4), **3** A-positive (cognate ligand regenerated by the overlay path), **4** A-negative (shape twin overlaid), **5** C-positive (cognate ligand through the edit pipeline with a null edit), **6** C-negative (contact-site edit), **7** C-control (solvent-exposed edit, label kept). Loss roles: MSE at the parent's label for kinds {0,1,3,5,7}; one-sided hinge below the parent's label for kinds {2,4,6} with per-kind margins (pK) `2:0.75, 4:1.0, 6:1.0`; rows of kinds not in `--train-kinds` are excluded before the sampler.
- **Matching rule:** a negative's ligand must be a positive somewhere in the training set (A twins come from the training ligand pool), and the positive of the same scheme goes through the same placement/minimisation/relief path as the negative (kind 3 vs 4, kind 5 vs 6/7). Crystal rows (kind 0) stay as they are.
- **Pose hygiene (reuse arm 4):** rigid-body soft-repulsion relief to 3.0 Å (`pose_augment.relieve_clash`), acceptance `min_dist >= min(2.2, crystal_min_dist)`, `contact_frac >= 0.5` of the crystal's contacts, `n_within_3A` and `min_dist` recorded; cue AUROCs (positive vs negative on `min_dist`, on `n_within_3A`, on heavy-atom count) written to each generator's summary.
- **Determinism:** `rng = default_rng(crc32(pdb))` per anchor; twin candidate lists are built once per anchor from fixed descriptor arrays.
- **Group-disjoint holdout:** `--holdout-groups 0.05 --holdout-group-min-rows 5` selects 5% of target groups (from `pocket_groups.csv`, `group_id`) with ≥ 5 rows, by `default_rng(0)`, and moves ALL their rows (all sources; original splits `train` and `series_valid`; `valid`/`test` rows of those groups stay where they are and are flagged `group_leak=1` in meta) to a new split `group_valid`. The baseline for every arm here is `base-g` = kinds {0} on this reduced train set.
- **Generators run only on PDBbind anchors with `split in {train, valid}`** (valid anchors feed the discrimination metrics, never training). K per anchor: A: 2 twins (kind 4) + 1 regenerated positive (kind 3); C: up to 2 contact edits (kind 6), up to 2 exposed edits (kind 7), 1 null-edit positive (kind 5).
- **Ligand pool for A:** every ligand with a descriptor in `zernike.npz` whose row has `split == train` (any source), excluding ligands sharing the anchor's `lig_key`, ligands that appear with the anchor's `group_id` anywhere (known binders), and ligands whose source structure cannot be read by RDKit.
- No commits. Everything testable locally except the AEV step (Isambard jobs).

## File formats (new)

**Generator pickles/meta** (same shape as arm 4): `work/data/twins.pickle` + `twins_meta.csv` + `twins_summary.json`; `work/data/edits.pickle` + `edits_meta.csv` + `edits_summary.json`. `unique_id`: A: `f"{pdb}::tpos0"` (kind 3), `f"{pdb}::twin{k}"` (kind 4); C: `f"{pdb}::epos0"` (kind 5), `f"{pdb}::cedit{k}"` (kind 6), `f"{pdb}::xedit{k}"` (kind 7). Meta columns (first ten fixed, then scheme-specific): `unique_id, pdb, kind, k, method, split, rmsd_to_crystal, min_dist, contact_frac, n_within_3A`, then A: `twin_unique_id, twin_source, shape_dist, complementarity, o3a_score, n_heavy_anchor, n_heavy_twin, dlogp, dcharge, darom`; C: `edit_rule, site_class, n_edited_atoms, n_contacts_edited_group, partner_type, mmff_restrained_rmsd`.

**Dataset:** `build_paired_dataset.py --poses-pickle/--poses-meta` become repeatable (`--aug PICKLE:META`, any number); `paired_meta.csv` gains `group_id`, `group_leak`; new split `group_valid` (`paired_group_valid.pt`); the existing `poses_valid` becomes generic: `paired_aug_valid.pt` holds every PDBbind `valid` crystal row plus all its augmented rows of every kind (the arm-4 `poses_valid` file is kept for backward compatibility when only poses are given).

**Evaluation:** `eval_paired.py --aug-pt FILE` → `aug_summary.csv` with one row per negative kind present: `kind, n_parents, rank_acc` (parent's positive-of-the-same-scheme prediction > max negative of that kind; for kind 2 the positive is the crystal), `gap_mean` (pK), and for control kinds (1, 3, 5, 7): `spread` (mean |pred − pred(crystal)|) and `pearson` (label vs pred); plus `--group-valid-pt FILE` → `group_valid_summary.csv` (pointwise Pearson/RMSE/Spearman; within-series Spearman over series with ≥ 5 rows if any).

## Review Focus

- An anchor whose ligand has no acceptable twin (small or very large ligands, charged peptides): A writes the positive only or nothing, records it, never raises. Test in Task A (`test_no_twin_records_failure`).
- Twin selection must never pick a ligand from the anchor's own group under any key (`lig_key`, `group_id`), including BindingNet rows modelled on the anchor's template. Test in Task A (`test_twin_excludes_own_group_and_ligand`).
- C edit rules must leave the molecule sanitisable with coordinates for every atom (new atoms placed by constrained embedding), and an edit that changes formal charge must update it. Test in Task C (`test_edits_are_sanitisable_with_coords`).
- The hinge must use the parent's label, not the edited/twin ligand's own (twins have labels in their own pocket). Test in Task D (`test_hinge_uses_parent_label`).
- Group holdout: no train row may share `group_id` with a `group_valid` row; `valid`/`test` rows in held-out groups are flagged, not moved. Test in Task D (`test_group_holdout_disjoint`).

### Task C: in-place edit generator and featuriser

**Files:** create `src/ligand_edits.py`, `src/featurise_edits.py`, `jobs/featurise_edits.sbatch`, `tests/test_ligand_edits.py`, `tests/test_featurise_edits.py`.

**Interfaces:**
- Consumes: PDBbind anchors (crystal ligand mol2 + protein), `pocket_fields.protein_fields` (typed protein atoms with channel weights, for site classification), `pose_augment` helpers.
- Produces: `ligand_edits.RULES`: an ordered list of `(name, reactant_smarts, product_smarts)` for: `cooh_to_me` (carboxylic acid/carboxylate → methyl), `amine_to_me` (primary amine/ammonium → methyl), `phenyl_to_chx` (six-membered all-carbon aromatic ring with ≤ 2 substituents → cyclohexyl), `oh_to_f` (hydroxyl → fluorine), `nh_to_o` (aromatic NH (pyrrole/indole type) → O, i.e. donor → acceptor), `amide_nh_to_nme` (secondary amide NH → N-methyl: donor removed). `apply_edit(mol_h, rule, match_idx) -> edited_mol_h` keeps all unedited atom coordinates, places new atoms by `AllChem.ConstrainedEmbed`-style coordinate-map embedding of the edited molecule with the unchanged heavy atoms fixed, then MMFF minimisation with the unchanged heavy atoms restrained (`MMFFGetMoleculeForceField` + `AddFixedPoint` or position constraints, ≤ 200 steps), then `relieve_clash` + acceptance; `rmsd` of unchanged atoms recorded as `mmff_restrained_rmsd`. `classify_site(edited_atom_idx, lig_xyz, protein_fields, rule) -> ("contact"|"exposed"|"ambiguous", n_contacts, partner_type)`: contact = ≥ 1 complementary protein atom within 4.0 Å of the edited group (acid: pos channel atom; amine: neg channel atom; phenyl: ≥ 3 hydrophobic/aromatic atoms within 4.5 Å; OH/NH donor: acceptor atom within 3.5 Å; amide NH: acceptor within 3.5 Å), exposed = no protein heavy atom within 4.5 Å of any edited atom, otherwise ambiguous (skipped). `null_edit(mol_h)` = the same embed-with-all-heavy-atoms-fixed + restrained MMFF + relief path with no change (kind 5). `generate_edits(anchor, protein_fields, rng, k_contact=2, k_exposed=2) -> list[EditPose]`. `featurise_edits.main(argv)`: `--meta --pdbbind-root --parent-data --out-dir --workers 72 [--limit N]` → `edits.pickle`, `edits_meta.csv`, `edits_summary.json` (counts per rule × site class × split, failure reasons, cue AUROCs kind5-vs-kind6 and kind5-vs-kind7 on min_dist/n_within_3A/heavy-atom count, `mmff_restrained_rmsd` quantiles).
